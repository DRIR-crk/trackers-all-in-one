# Trackers All-in-One

A single, deduplicated list of public BitTorrent trackers, merged from several community-maintained sources.
Add it to your torrent client to speed up peer discovery for public torrents.

> **PT-BR:** Uma lista única de trackers públicos de BitTorrent, sem duplicatas, reunida a partir de várias fontes da comunidade. Todo o crédito vai para os mantenedores originais (veja **Credits** abaixo).

## What's inside

- **[`trackers_all_in_one.txt`](trackers_all_in_one.txt)** — the full union of every source (maximum coverage).
- **[`trackers_best.txt`](trackers_best.txt)** — **our own** list: every tracker in the full list is probed live each week (a real UDP/HTTP handshake) and only the ones that actually respond are kept.

Both are plain text, one tracker URL per line, duplicates removed.

## Usage

Direct raw links (paste into your client or script):

```
# Full list — maximum coverage
https://raw.githubusercontent.com/DRIR-crk/trackers-all-in-one/main/trackers_all_in_one.txt

# Live-tested subset — only trackers that responded this week
https://raw.githubusercontent.com/DRIR-crk/trackers-all-in-one/main/trackers_best.txt
```

- **qBittorrent** → Options → BitTorrent → *Automatically add these trackers to new downloads* → paste the list.
- **Transmission / Deluge / Vuze / BiglyBT** → add trackers to a torrent, one URL per line.

## How it was built

The list is regenerated by [`scripts/update.sh`](scripts/update.sh), run weekly by
[`.github/workflows/update-trackers.yml`](.github/workflows/update-trackers.yml). The script:

1. Downloads each upstream list (see **Credits**) with a browser user-agent, **skipping any source that is temporarily unreachable** so one outage can't break the run.
2. Prepends a hand-picked, in-repo list ([`sources/extra.txt`](sources/extra.txt)) so your own trackers survive every refresh.
3. Keeps only valid tracker URLs, trims whitespace, and removes duplicates (first occurrence wins) → **`trackers_all_in_one.txt`**.
4. **Live-tests every tracker** with [`scripts/check_trackers.py`](scripts/check_trackers.py) and keeps only the ones that respond → **`trackers_best.txt`**.

Each file is written only if it clears a minimum count, so a network hiccup never wipes a published list.

### The liveness test ([`scripts/check_trackers.py`](scripts/check_trackers.py))

This is what makes `trackers_best.txt` *ours* rather than a copy of someone else's "best" list. A tracker counts as alive only if it actually answers the BitTorrent tracker protocol — not just a ping:

- **`udp://`** — performs the [BEP 15](https://www.bittorrent.org/beps/bep_0015.html) handshake: a *connect* request, then an *announce*. It must reply with a well-formed packet (matching transaction id).
- **`http(s)://`** — sends a real *announce* request; the response must be valid **bencode** (a live tracker, even one returning a "failure reason", passes — an HTML error page or a timeout does not). TLS certificate errors are ignored so a working tracker with a bad cert still counts.
- **`ws(s)://`** — WebSocket/WebTorrent trackers aren't probed, so they're excluded from `best` (they stay in the full list).

Probing runs in parallel with per-tracker timeouts. Because it's a live test, `trackers_best.txt` reflects what was actually reachable from GitHub's runners at build time — run it yourself with `python3 scripts/check_trackers.py trackers_all_in_one.txt out.txt`.
